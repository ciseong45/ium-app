# 이음 순신청·배정 구현 상세 설계안

작성일: 2026-09-22 · 담당 관점: Media & Tech Owner

문서 상태: 구현을 위한 제안 명세. 코드 변경·DB 적용·배포는 이 문서 작성 범위에 포함하지 않는다. 현재 구조는 로컬 코드로 확인했으며 운영 DB의 실제 적용 상태는 구현 시작 시 점검한다.

이 문서는 `small-group-registration-design-2026-09-22.md`의 상세 구현 기준이다. 차이가 있는 경우 이 문서를 우선한다. 모집 날짜·대상·교육 수료 조건은 설정값이며 임의 확정하지 않는다.

## 1. 목표와 확정된 제품 방향

1. 성도는 계정 없이 웹사이트 또는 QR로 순신청한다.
2. 이름과 전체 연락처가 기존 성도 한 명과 정확히 일치하면 자동 후보를 붙여 바로 배정 대기로 보낸다.
3. 담당자는 자동 일치 건의 연결 버튼을 따로 누르지 않는다. 배정 확정 시 연결까지 함께 처리한다.
4. 동명이인·연락처 변경·중복·신규만 예외로 확인한다. 예외가 남아 있어도 다른 사람의 배정을 진행한다.
5. 운영 화면은 학기별 `순별 명단 / 신청·배정 / 모집 설정` 3개 탭이다.
6. 배정안은 제안일 뿐이다. 확정해야 실제 순원 명단과 출석·돌봄 조회에 반영된다.
7. 현재 학기와 다음 학기 모집은 독립적으로 운영한다.

첫 버전 제외: 성도 로그인, 본인 신청 조회·수정, 자동 문자·카카오 발송, 알고리즘에 의한 자동 순배정, 드래그앤드롭, 임의 항목 폼 빌더, 교육 프로그램 자체 재설계. QR 생성과 다운로드는 포함한다.

## 3. 정보 구조와 URL

| 화면 | 제안 경로 | 비고 |
| --- | --- | --- |
| 소그룹 진입 | `/small-groups` | 활성 학기의 명단으로 이동. 없으면 학기 선택 화면 |
| 순별 명단 | `/small-groups/[seasonId]?tab=roster` | 기본 탭 |
| 신청·배정 | `/small-groups/[seasonId]?tab=applications&campaign=[id]` | 모집 선택, 필터와 페이지를 URL에 유지 |
| 모집 설정 | `/small-groups/[seasonId]?tab=campaigns&campaign=[id]` | 관리자만 접근 |
| 공개 모집 목록 | `/group-apply` | 공개된 모집 카드, 열림·예정·마감 상태 표시 |
| 공개 신청서 | `/group-apply/[slug]` | QR과 웹사이트 버튼의 동일 목적지 |
| 기존 여름 신청 | `/summer-apply` | 과거 접수 종료 안내, 새 모집 목록 버튼 |

- 학기 선택기는 ‘운영 중 / 예정 / 지난 학기’를 날짜와 활성 상태로 구분한다. 모든 비활성 학기를 ‘이전 시즌’으로 표시하는 기존 방식은 수정한다.
- 탭을 바꿔도 학기는 유지한다. 학기를 바꾸면 해당 학기에 없는 모집·선택 행·배정 상세는 초기화한다.
- 모집은 학기당 여러 개를 허용한다. 첫 버전도 모집 선택기를 두되 1개이면 이름만 표시한다.
- 접근 권한 없는 탭은 숨기고 URL 직접 접근도 거부한다. 탭을 숨기는 것만으로 권한을 구현하지 않는다.
- 과거 여름 데이터는 해당 학기의 과거 모집으로 남긴다. 여름이라는 이유로 별도 업무 탭을 유지하지 않는다.

## 4. 화면 명세

### 4.1 공개 신청서

상단: 교회명, 모집명, 대상, 접수 기간과 시간대, 배정 안내 문구. 본문: 아래 항목. 하단: 문의 방법과 정보 이용 안내.

| 입력 | 규칙 | 저장 |
| --- | --- | --- |
| 이름 | 필수, 공백 제거 후 1~80자. 한글·영문 이름 허용 | 입력 원문 + 대조용 정규화 값 |
| 연락처 | 필수. 국가 선택 + 번호. 기본 US, 다른 국가 허용 | 입력 원문 + 검증된 국제 표준형 번호 |
| 신청 구분 | `new / continuing / change` 중 모집에서 허용한 값 | `application_kind` |
| 참고사항 | 선택, 최대 500자. HTML로 해석하지 않음 | `note` |
| 정보 이용 안내 확인 | 필수. 공개된 문구와 버전 표시 | 서버 시각 + 버전 |

국제 번호 검증은 검증된 번호 파서를 사용한다. 서식이 유효해도 실제 소유 확인을 의미하지 않는다. 전화 끝자리만으로 매칭하지 않는다. 전화가 없는 경우 공개 폼에서 예외값을 넣게 하지 않고 담당자의 대리 접수를 안내한다.

모집의 `audience_mode`가 `all`이면 3개 신청 구분, `new_and_change`이면 신규·변경을 제공한다. 선택지 노출과 서버 검증이 일치해야 한다. 첫 버전의 대상 안내는 공개 문구이며 기존 교인 자격을 공개 폼에서 조회해 검증하지 않는다.

동작:

1. 입력 오류는 해당 항목 아래 표시하고 첫 오류로 초점을 이동한다.
2. 제출 중 버튼을 비활성화한다. 서버 제출 식별키는 응답을 잃어버린 재시도에도 유지한다.
3. 저장 성공 후만 완료 화면을 표시한다. 완료 화면에는 개인 이력·성도 존재 여부·교육 상태·기존 순을 표시하지 않는다.
4. 서버 오류나 네트워크 오류면 입력은 보존하고 재시도한다. 단순 제출 버튼 재클릭으로 중복 레코드를 만들지 않는다.
5. 마감 이후에는 열어 둔 폼도 접수하지 않는다. 이미 성공한 동일 제출의 재시도는 기존 성공으로 반환한다.
6. 정상 신청과 기존 성도 여부·중복 의심 여부의 공개 응답 형태를 동일하게 유지한다.
7. 첫 버전은 완료 화면에서 수정·취소 문의 경로만 제공한다. 접수번호로 개인 기록을 조회하는 기능은 만들지 않는다.

### 4.2 신청·배정: 데스크톱

```text
학기 [선택]      순별 명단 | 신청·배정 | 모집 설정
모집 [선택]      접수 중 · 기간                 [링크 복사] [QR]
유효 신청 00건   자동 일치 00건   확인 필요 00건   확정 00건

[배정 대기] [확인 필요] [배정안] [확정] [전체] [중복·취소]
[이름·전화 검색] [교육 상태] [현재 순] [신청 구분]
┌ 신청자 목록: 약 60% ────────────────┬ 순별 배정안: 약 40% ──┐
│ □ 이름 / 연결 상태 / 교육 / 현재 순 │ A순 · 순장             │
│   요청사항 / 제안 순 / 처리 상태     │ 현재 6 · 추가 2 · 이동 1 │
│ □ …                               │ 확정 후 예상 7         │
│   [상세] [순 선택]                  │ B순 …                  │
└────────────────────────────────────┴────────────────────────┘
선택 00건   [선택 항목에 순 지정] [배정안 해제] [연결·배정 확정]
```

- 기본 필터는 배정 대기. 신청 직후 자동 일치 건은 이 목록으로 들어간다.
- 체크박스 선택은 현재 페이지 범위로 시작한다. ‘전체 검색 결과 선택’은 첫 버전에서 제공하지 않는다.
- 페이지당 기본 50건, 최대 100건. 일괄 확정 최대 100건. 검색은 이름·전화 정규화 기준, 300ms 지연 요청.
- 필터·모집·학기·페이지를 바꾸면 선택을 해제하고 알려준다. 보이지 않는 행이 몰래 확정되지 않도록 한다.
- 행마다 순 선택 드롭다운으로 배정안을 저장한다. 신규·확인 필요 신청도 배정안 작성은 가능하다.
- 확정 버튼에는 현재 선택 중 확정 가능한 수와 제외 사유를 표시한다. 확인 필요자를 자동으로 건너뛰고 성공한 척하지 않는다.
- 오른쪽 순별 인원은 현재 명단과 이 모집의 배정안으로 계산한다. 같은 순 유지 0, 이동 출발 순 -1, 도착 순 +1, 신규 +1. 연결되지 않은 배정안은 별도 ‘미확인 제안 N건’으로 표시하고 확정 인원 계산에 섞지 않는다.
- 같은 학기의 다른 모집에도 활성 배정안이 있으면 충돌 안내를 표시한다. 현재 모집의 예상 인원이 학기 전체 확정 예상치인 것처럼 보이지 않게 한다.
- 정원은 첫 버전의 강제 제약으로 두지 않는다. 순별 인원·구성을 보고 담당자가 판단한다.
- 신청 목록의 일반 행은 연락처를 마스킹한다. 허용된 담당자는 상세에서 전체 번호를 확인한다.

### 4.3 모바일

- 목록을 카드형으로 표시하고 `신청자 / 순별 현황` 전환을 제공한다.
- 카드의 ‘순 선택’으로 배정안을 저장한다. 상세 확인은 전체 높이 패널로 연다.
- 선택 후 하단 고정 작업 영역을 표시하되 키보드·안전 영역에 가리지 않게 한다.
- 터치·키보드로 모든 배정 동작이 가능해야 한다. 끌어놓기에 의존하지 않는다.
- 현재 앱의 색상·서체·여백 토큰을 재사용한다. 상태는 색상뿐 아니라 텍스트로 표시한다.

### 4.4 예외 상세 패널

| 구역 | 내용과 동작 |
| --- | --- |
| 원본 신청 | 제출한 이름·전화·구분·메모·시각, 원문 수정 금지 |
| 자동 대조 결과 | 일치/불일치 이유, 후보 이름·연락처·현재 순. 예외 후보가 없으면 기존 성도 검색 |
| 기존 성도 연결 | 후보 선택 후 확인. 다른 유효 신청·기존 배정 충돌을 먼저 보여줌 |
| 신규 성도 | 기존 명단 재검색 → 이름 구성·연락처 확인 → 신규 작성 준비. 정식 교인 등록과 구분 |
| 중복 신청 | 대표 신청과 입력 차이 비교, 대표 선택. 원문 보존 |
| 변경 요청 | 담당자 수정은 별도 정정 필드와 이력에 저장. 원본 성도 연락처는 별도 명시적 수정 동작 필요 |
| 교육 | 공통 교육 상태, 기록 없음, 기록 충돌은 확인 필요. 후보 단계는 ‘자동 대조 기준’ 표시 |
| 작업 이력 | 연결·정정·배정·취소·안내 기록 |

신규 성도 정보는 담당자가 검토한 임시 자료로 저장할 수 있다. 실제 성도 생성은 연결·배정 확정 시 함께 수행한다. 신청자마다 새가족 교육 기록을 자동 생성하지 않는다.

### 4.5 확정 검토 창

제목: `선택한 N건의 성도 연결·순배정을 확정합니다`.

각 행에 신청자, 연결 대상, 기존 순 → 제안 순, 신규/이동/유지, 충돌 사유를 표시한다. 자동 일치 건은 이 창이 유일한 연결 확인 단계다. 신규 성도 생성 건수와 같은 학기 이동 건수를 별도 요약한다.

- ‘확정’ 전 서버 사전 검증을 수행한다. 예외는 이유와 함께 선택에서 제외하도록 요청한다.
- 사전 검증은 잠금이 아니다. 확정 시 버전·일치 조건·권한을 다시 검사한다.
- 저장 중 중복 클릭을 막고, 성공 시 서버 결과로 목록·순별 명단·건수를 갱신한다.
- 실패 시 완료 표시나 낙관적 순원 추가를 하지 않는다. 일부 실패가 전체 성공으로 보이지 않게 한다.
- 안내 발송은 수행하지 않는다. 확정 목록의 ‘안내 완료’는 담당자가 실제 연락 후 수동 기록한다.

### 4.6 순별 명단과 모집 설정

순별 명단은 기존 다락방·순·순장 카드 구조를 재사용한다. 확정 순원만 인원에 포함하고 신청 건을 중복 합산하지 않는다. 기존 성도 추가·이동·제외 버튼도 동일한 배정 서비스를 사용한다.

모집 설정 필수값: 모집명, 대상 학기, 모집 코드, 대상 구분, 대상 안내, 시작·마감, 시간대, 배정 안내 문구, 문의 경로, 정보 이용 안내 버전·본문. 연락 안내 시점이 미정이면 구체적인 날짜를 표시하지 않는다.

모집 코드는 소문자 영문·숫자·하이픈 3~80자, 전체에서 고유하다. 첫 공개 이후 변경 금지. 신청이 한 건이라도 있으면 대상 학기도 변경 금지. 공개 전 미리보기 가능. 공개 후 문구 변경은 버전을 남긴다.

QR은 모집 고정 URL만 인코딩한다. 개인정보·인증 토큰을 넣지 않는다. PNG 다운로드와 링크 복사를 지원하고 실제 휴대전화 스캔으로 주소를 검증한다. 웹사이트에는 확정된 모집 링크·대상·기간을 표시하며 폼을 복제하지 않는다.

## 5. 상태·필터·집계의 정확한 정의

### 모집 상태

저장 상태 `draft / published / paused / archived`. 화면의 접수 상태는 서버 시각으로 계산한다.

| 조건 | 화면 | 접수 |
| --- | --- | --- |
| draft | 관리자 미리보기, 공개 주소에서는 찾을 수 없음 | 불가 |
| published, now < opens_at | 접수 예정 | 불가 |
| published, opens_at ≤ now < closes_at | 접수 중 | 가능 |
| published, now ≥ closes_at | 접수 마감 | 불가 |
| paused | 일시 중지 | 불가 |
| archived | 종료 안내 | 불가 |

기본 입력 시간대 `America/New_York`, DB 저장 `timestamptz`. 마감 시각은 포함하지 않는다. 기간 수정은 이력 기록 후 반영한다. 마감 뒤 내부 추가 접수는 권한 있는 담당자가 사유를 남길 때만 허용한다.

### 신청과 연결 상태

DB 신청 상태는 `pending / drafted / confirmed / cancelled / duplicate / legacy_review`.
DB 연결 상태는 `exact_candidate / review_required / new_candidate / new_prepared / linked`.

| 사용자 필터 | 조회 조건 |
| --- | --- |
| 배정 대기 | pending + 연결 상태 exact_candidate, linked, new_prepared 중 하나 |
| 확인 필요 | pending 또는 drafted + review_required 또는 new_candidate |
| 배정안 | drafted 전체. 확인 필요 여부를 행별 표시 |
| 확정 | confirmed |
| 중복·취소 | duplicate 또는 cancelled |
| 기존 신청 확인 | legacy_review. 전환 데이터가 있을 때만 표시 |
| 전체 | 해당 모집의 모든 상태 |

`new_prepared`는 신규 정보 검토를 마친 상태이며 배정안이 있으면 확정 가능하다. 연결 상태와 신청 상태는 독립 축이므로 필터 숫자는 합계가 아닐 수 있다.

- 유효 신청 수 = pending + drafted + confirmed. 연결 전에는 ‘명’이 아닌 ‘건’으로 표시한다.
- 자동 일치 수 = pending 또는 drafted의 exact_candidate.
- 확인 필요 수 = 위 필터 조건. 중복 의심·보관 성도·휴적/제적 관련 검토도 포함한다.
- 확정 수 = confirmed. 실제 현재 순원 수와 별개다.
- 모든 수치는 모집 전체 기준, 검색 결과 건수는 목록에 별도 표시한다. 조회 실패를 0건으로 반환하지 않는다.
- 전이: pending → drafted → confirmed. drafted → pending은 배정안 해제. 확정 전 취소는 cancelled. 중복 판정은 duplicate. 확정 후 해제는 별도 취소 작업으로 처리한다.
- 중복 대표는 같은 모집 안의 신청이어야 하며 자기 참조·순환 참조를 금지한다. 대표를 취소해도 중복 신청이 자동 부활하지 않는다.

## 6. 성도 자동 대조 규칙

1. 이름은 Unicode NFC 정규화, 앞뒤·사이 공백 정리, 영문 대소문자 통일을 적용한다. 순서 바꾸기·별명 추정·음역·철자 유사도는 자동 일치에 쓰지 않는다.
2. 기존 `last_name + first_name`과 동일 규칙으로 대조한다. 영문 이름 순서 차이는 수동 후보 제안으로만 처리한다.
3. 연락처는 국가 정보가 확실하고 파싱이 유효할 때만 국제 표준형으로 정규화한다. 애매한 기존 번호는 확인 필요다.
4. 이름+전체 번호 조합이 정확히 한 성도에 일치하고 신청 중복·상태 충돌이 없으면 exact_candidate.
5. 이름 또는 전화만 일치하면 review_required. 둘 다 후보가 없으면 new_candidate. 가족 공용 번호는 이름+번호 조합으로 구분하며 전화 단독 고유 제약을 만들지 않는다.
6. `on_leave`, `removed`, 보관된 새가족 기록과 충돌하는 후보는 담당자가 상태를 확인해야 한다. 자동으로 재적 상태로 변경하지 않는다.
7. 같은 모집에 같은 후보/확정 성도를 가리키는 별도 신청이 생기면 미확정 신청을 중복 검토 대상으로 표시한다. 이미 확정된 명단은 유지한다.
8. 후보 ID·규칙 버전·대조 시각·입력 fingerprint·대조한 성도 정보 fingerprint를 저장한다. 확정 직전에 다시 검증한다.
9. 후보 연결은 관리자 내부 정보다. 공개 응답·공개 페이지·로그인 권한·원본 성도 수정에 사용하지 않는다.
10. 매칭 실패와 접수 저장 실패를 분리한다. 신청은 저장됐지만 대조가 실패하면 review_required와 시스템 사유를 남기고 내부 재대조가 가능해야 한다.

교육은 성도 ID를 통해 기존 공통 계산 로직으로 읽는다. 여러 교육 기록이 충돌하면 확인 필요로 표시한다. 교육 기록이 없는 기존 멤버를 미이수로 단정하지 않는다. 기본 수료 정책은 `reference_only`로, 자동 배정 거절 조건이 아니다.

## 7. 데이터 모델

아래 이름과 자료형은 신규 구현 기준이다. 기존 ID 자료형은 실제 DB 조회로 확인하고 FK의 자료형을 맞춘다. `version`은 변경마다 증가하는 정수로, 이전 화면에서 저장하는 충돌을 검출한다.

### 7.1 신규 `small_group_campaigns`

| 필드 | 타입·규칙 |
| --- | --- |
| id | bigint identity PK |
| season_id | 기존 학기 ID, FK, 삭제 RESTRICT |
| slug | text UNIQUE NOT NULL, 공개 후 불변 |
| title / audience_description / intro | text, 각각 최대 100 / 500 / 2,000자 |
| audience_mode | all 또는 new_and_change |
| status | draft / published / paused / archived |
| opens_at / closes_at | timestamptz, 공개 시 필수, opens_at < closes_at |
| timezone | 유효한 IANA 시간대, 기본 America/New_York |
| announcement_text / contact_text | text, 각각 최대 1,000 / 500자, 공개 시 필수 |
| notice_version / notice_text | 정보 이용 안내 버전과 본문, 공개 시 필수 |
| retention_review_at | 신청 자료 보관 검토일, 공개 전에 운영자가 설정. 자동 삭제일이 아님 |
| education_policy | 첫 버전 reference_only만 지원 |
| version / created_at / updated_at / created_by | 버전, 서버 시각, 관리자 프로필 FK |

공개된 모집 설정 변경은 별도 이력에 이전 값을 저장한다. 공개 조회에는 위 필드 중 성도 안내에 필요한 항목만 반환한다. 내부 작성자·권한 목록은 포함하지 않는다.

### 7.2 신규 `small_group_campaign_operators`

`campaign_id, profile_id, assigned_by, created_at`, PK `(campaign_id, profile_id)`.

관리자가 승인된 다락방장을 해당 모집의 운영 담당자로 지정한다. 지정은 해당 모집 전체의 접수·대조·배정 권한을 뜻하며, 다른 모집 권한으로 확대되지 않는다. 프로필이 비승인 상태로 바뀌면 지정이 남아 있어도 권한을 잃는다.

### 7.3 확장 `small_group_applications`

| 필드 | 의미·제약 |
| --- | --- |
| id / campaign_id / season_id | 기존 신청 ID 유지. 모집과 학기는 복합 FK로 일치시킴 |
| name / phone / note | 제출 원문, 제출 이후 불변 |
| corrected_name / corrected_phone / corrected_note | 담당자 정정. 정정 사유·이력 필수, 자동 매칭 재계산 |
| normalized_name / normalized_phone | 원문 또는 승인된 정정 값에서 생성한 대조용 값 |
| application_kind | new / continuing / change. 과거 자료만 NULL 허용 |
| source | form / admin / legacy |
| submission_key / payload_hash | 공개 제출 UUID, 정규화된 제출 내용 해시. 캠페인 내 식별키 UNIQUE |
| candidate_member_id | 자동 후보 FK, NULL 가능 |
| member_id | 확인 완료 성도 FK, NULL 가능. 후보를 여기에 미리 쓰지 않음 |
| match_status / match_reason | 5절 연결 상태, 기계 판독 가능한 사유 코드 |
| match_version / matched_at / match_fingerprint | 규칙 버전, 시각, 입력·기존 기록 대조 근거 |
| prepared_member | 담당자가 확인한 신규 생성용 구조화 자료. 이름 구성·전화·초기 상태 visitor |
| status | pending / drafted / confirmed / cancelled / duplicate / legacy_review |
| proposed_group_id | 배정안 FK. 같은 학기의 순만 허용 |
| assigned_group_id / confirmed_at / confirmed_by | 확정 당시 순과 시각·수행자. 당시 기록으로 보존 |
| duplicate_of_id | 대표 신청 FK. 같은 모집 검증, 대표는 duplicate일 수 없음 |
| informed_at / informed_by / informed_method | 실제 수동 안내 기록. 자동 발송 기능 아님 |
| consent_version / consented_at | 공개 신청 필수. 대리 접수는 확인 방식·사유를 이력으로 남김 |
| review_flags | 중복 의심, 정보 변경, 교육 기록 충돌 등 사유 코드 배열 |
| legacy_snapshot | 이전 상태·배정 정보를 보존하는 전환 원본 |
| version / applied_at / updated_at | 서버 관리 값 |

`prepared_member`에는 임의 JSON을 저장하지 않고 허용 필드·길이를 검증한다. 연락처가 없는 대리 접수는 전화 NULL과 예외 사유를 허용하되 자동 일치에서 제외한다.

DB 제약:

- `(campaign_id, submission_key)` 고유. 같은 키와 다른 내용이면 제출 충돌 오류이며 덮어쓰기 금지.
- 유효 상태의 `(campaign_id, member_id)` 부분 고유 인덱스. NULL 후보는 제외, 취소·중복·legacy_review는 제외.
- drafted는 proposed_group_id 필수. confirmed는 member_id·assigned_group_id·confirmed_at·confirmed_by 필수.
- exact_candidate는 candidate_member_id 필수, linked는 member_id 필수, new_prepared는 검증된 prepared_member 필수다. 자동 후보와 신규 준비 상태에서 확정 member_id를 미리 기록하지 않는다.
- 같은 학기 순을 참조하도록 `(proposed_group_id, season_id)`와 `(assigned_group_id, season_id)` 복합 FK 사용.
- 복합 FK를 위해 campaigns와 small_groups의 `(id, season_id)` UNIQUE 제약을 추가한다. 이미 참조된 순의 season_id는 변경을 금지한다.
- 취소·확정 기록이 있는 성도·순·모집은 삭제보다 보관을 사용한다. 기존 `ON DELETE CASCADE`가 신청·명단 이력을 지우지 않도록 관련 삭제 정책도 함께 변경한다.
- 목록 인덱스 `(campaign_id, status, applied_at, id)`, 대조 인덱스 `(normalized_name, normalized_phone)`, `candidate_member_id`, `member_id`.

### 7.4 `small_group_members`: 확정 명단 원본

기존 필드에 `season_id`, `version`, `updated_at`, `updated_by`를 추가한다.

- `UNIQUE(season_id, member_id)`로 성도당 학기 내 하나의 순만 허용한다.
- `(group_id, season_id)`가 실제 순의 `(id, season_id)`를 참조하도록 복합 FK를 둔다.
- 같은 학기의 이동은 기존 명단 행의 group_id를 갱신하고 이력에 이전 순을 남긴다.
- 다른 학기의 명단은 유지한다. 다중 순 소속이 실제로 필요하다면 적용 전에 정책을 바꿔야 하며 기존 중복을 임의 삭제하지 않는다.
- 신청서 assigned_group_id는 확정 당시의 기록이다. 이후 명단에서 이동하면 상세에 ‘확정 당시 A순 / 현재 B순’을 구분해서 표시한다.
- 확정 신청 취소 시 신청서에 적힌 옛 순을 근거로 현재 순원을 삭제하지 않는다. 현재 명단의 버전·이동 이력을 확인한다.

### 7.5 신규 이력·작업·대조 보조 구조

| 테이블 | 핵심 필드와 목적 |
| --- | --- |
| `small_group_operation_log` | id, operation_id, campaign_id nullable, application_id nullable, season_id, member_id nullable, actor_id, action, before/after 제한 JSON, reason, created_at. append-only |
| `small_group_operations` | operation_id UUID PK, actor_id, payload_hash, result, created_at. 확정 재시도에 이전 결과 반환, 다른 내용으로 키 재사용 금지 |
| 내부 rate limit 저장소 | 서버가 만든 IP HMAC·기간·횟수. 원문 IP·신청 내용 로그 금지, 짧은 TTL |

성도의 대조용 이름·전화는 members의 정규화 컬럼 또는 비공개 검색 테이블로 관리한다. 공개 열람은 허용하지 않는다. 성도 편집·방문 접수 등 모든 생성/수정 경로에서 대조값이 함께 갱신되어야 한다.

## 8. API·서버 작업 계약

공개 경로는 Route Handler, 내부 변경은 인증된 Server Action → DB 함수로 구성한다. 아래 이름은 신규 구현에서 사용할 제안이다. 화면이 직접 테이블을 변경하지 않도록 한다.

공통 내부 반환:

```ts
type ActionResult<T> =
  | { ok: true; data: T }
  | { ok: false; code: ErrorCode; message: string;
      conflicts?: { applicationId: number; code: string }[] };
```

| 작업 | 입력 | 결과·규칙 |
| --- | --- | --- |
| `GET /api/group-campaigns/[slug]` | slug | 공개 안내 DTO. 권한/신청/성도 원본 없음 |
| `POST /api/group-applications` | slug, submissionKey, name, phone, country, kind, note, consentVersion, consentAccepted | 201 접수 완료, 동일 성공 재시도 200. ID·매칭 결과 반환하지 않음 |
| `getApplications` | campaignId, status/match 필터, 검색, page | 최소 필드 목록 + 전체 집계 + 페이지 정보. 권한 검증 후 조회 |
| `getApplicationDetail` | applicationId | 허용된 원본·후보·교육·이력만 반환 |
| `reconcileApplications` | campaignId, 선택 IDs 또는 cursor | 100건 이내 단위로 대조, 실패 항목 식별. 확정 이력은 자동 변경하지 않음 |
| `resolveApplication` | id, expectedVersion, 기존 성도 선택 또는 신규 준비 자료, reason | 연결/신규 준비 상태 저장, 중복 검증, 버전 증가 |
| `correctApplication` | id, expectedVersion, 정정 필드, reason | 원문 보존, 대조 초기화, 배정안은 유지하되 확정 재검증 |
| `markDuplicate` | id, 대표 id, 두 expectedVersion, reason | 원문 보존, 대표 유효성 검증. 이미 확정된 건에는 직접 사용 불가 |
| `saveAssignmentDrafts` | campaignId, `{id, expectedVersion, groupId|null}[]` | 배정안만 저장/해제, 실제 순원 변화 없음 |
| `previewAssignments` | 선택 id/version | 기존/예상 순, 신규 생성, 유효 항목, 예외, 현재 명단 버전. 쓰기 없음 |
| `confirmAssignments` | operationId, campaignId, 선택 id/version + expectedMembershipVersion | 연결·생성·배정·이력 원자 저장. 최대 100건 |
| `cancelApplication` | id, expectedVersion, reason | 미확정 건만 취소, 배정안 해제 |
| `revokeConfirmedAssignment` | id, expectedVersion, expectedMembershipVersion, targetGroupId|null, reason | 현재 소속 확인 후 이동/제외와 신청 취소를 함께 처리 |
| `markInformed` | 선택 id/version, method | 실제 안내 후 기록, 외부 메시지 발송 없음 |
| `saveCampaign / setCampaignStatus` | 설정 + expectedVersion | 관리자만. 공개 필수값 검증, 이력 기록 |
| `setCampaignOperators` | campaignId, profileIds | 관리자만. 승인된 역할 검증 |
| `moveRosterMember` | seasonId, memberId, targetGroupId|null, expectedVersion, reason | 신청을 통하지 않는 명단 편집도 동일 불변식·이력 적용 |

오류 코드 최소 목록: `VALIDATION_ERROR`, `CAMPAIGN_NOT_OPEN`, `NOTICE_CHANGED`, `RATE_LIMITED`, `SUBMISSION_KEY_CONFLICT`, `FORBIDDEN`, `NOT_FOUND`, `VERSION_CONFLICT`, `MATCH_CHANGED`, `DUPLICATE_REVIEW_REQUIRED`, `GROUP_SEASON_MISMATCH`, `MEMBERSHIP_CONFLICT`, `ALREADY_CHANGED`, `INTERNAL_ERROR`.

공개 오류는 입력·기간·요청 빈도만 설명한다. 성도 유무·후보 수·개인정보는 포함하지 않는다. SQL 메시지나 비밀 키를 응답하지 않는다. 내부 충돌은 권한이 있는 신청 ID와 복구 방법만 전달한다.

## 9. 원자적 배정 확정과 동시 작업

DB 함수 제안: `confirm_small_group_assignments`. 수행자는 인증된 세션에서 얻고 클라이언트 actor_id를 신뢰하지 않는다.

```text
BEGIN
  수행자·모집 권한 검증
  operation_id 조회 → 같은 요청 완료면 이전 결과 반환
  같은 키에 다른 요청이면 거절
  operation_id 예약
  모집과 선택 신청의 대상 학기 검증
  학기 배정 잠금 → 선택 신청을 ID 순으로 잠금
  신청 version, 제안 순, 성도 후보, 현재 소속 version 다시 검증
  신규 준비 건: 대조 키 잠금 후 기존 성도 중복을 재검사
  예외가 하나라도 있으면 선택 작업 전체 ROLLBACK
  자동 후보 → member_id 확정 / 검토된 신규 → visitor 성도 생성
  실제 순원 INSERT 또는 같은 학기의 소속 UPDATE
  기존 순 유지 신청은 명단 중복 생성 없이 신청만 확정
  신청 confirmed + 확정 당시 순 저장
  각 연결·생성·이동 이력 저장
  작업 결과 저장
COMMIT
```

- 모든 순배정 진입점은 같은 학기 단위 잠금 규칙을 따른다. 첫 버전은 명료한 학기 잠금으로 동시 확정을 직렬화한다.
- 대조 키와 성도 행의 변경도 보호한다. 신규 생성 시 `(정규화 이름, 전화)` 키 잠금 후 재대조하고, 기존 members 삽입·이름/전화 변경 경로도 같은 키 잠금 규칙에 참여시킨다. 여러 키를 잠글 때 정렬 순서를 고정한다.
- 회원 생성 트리거는 대조 키만 관리하고 배정 잠금을 잡지 않도록 역할을 나눈다. 실제 새가족순 배정 진입점은 학기 잠금을 먼저 얻도록 수정해 잠금 순서 역전과 교착을 막는다. 구현 시 모든 관련 쓰기 경로를 함께 감사한다.
- 중복 고유 제약은 잠금 누락에 대한 마지막 방어다. 충돌을 무시하고 성공 처리하지 않는다.
- 미리보기 후 다른 담당자가 수정하면 VERSION_CONFLICT. 해당 행을 다시 불러오고 사용자가 배정안을 확인한다.
- 일부 예외는 사전 검토 화면에서 제외해 나머지로 새 작업을 만들 수 있다. 이미 시작한 단일 작업을 부분 성공시키지 않는다.
- 네트워크 응답 유실 후 동일 operation_id로 재시도하면 기존 결과를 돌려준다. 새로운 작업처럼 재배정하지 않는다.
- 확정 후 연결 오류 정정은 관리자 전용 복구 작업으로 원래 명단 버전과 관련 이력을 확인한다. 신청의 member_id만 바꾸는 직접 수정은 금지한다.

- 승인 대기 계정은 내부 권한이 없다. 역할과 linked_member_id의 변경 권한도 점검해 자기 역할 승격으로 우회할 수 없어야 한다.
- 공개 입력에는 member_id, candidate_member_id, status, assigned_group_id, actor_id를 받지 않는다. JSON에 포함돼도 거절한다.
- 공개 POST만 서버 전용 권한으로 제한된 접수 DB 함수를 호출한다. 함수 실행은 서버 역할에만 허용하고 anon/authenticated의 직접 신청 INSERT 및 접수 RPC 권한을 제거한다. 서비스 키는 서버 전용 모듈에만 둔다.
- 내부 확정 함수는 authenticated 실행을 허용하되 함수 안에서 관리자/모집 담당자 여부를 다시 검증한다. 고정 search_path와 명시적 객체 참조를 사용한다.
- 내부 테이블 직접 UPDATE/DELETE 권한을 제거하고 승인된 함수만 변경하도록 한다. 후보 조회도 최소 정보 DTO를 반환한다.
- 기존 넓은 RLS 정책은 새 제한 정책을 추가하는 것만으로 축소되지 않는다. 실제 정책·권한·뷰·RPC를 조사하고 겹치는 허용 경로를 제거한다.
- 기존 members/new_family 등 다른 경로를 통해 같은 신청·교육 정보가 노출되지 않는지도 확인한다. UI의 마스킹과 API 권한 검증을 구분한다.
- 초기 공개 제한 제안: 신뢰할 수 있는 서버 접속 IP 기준 10분 30회, 초과 시 429와 재시도 안내. 예배당 공용망을 고려해 운영값으로 조정 가능하게 한다. 신청 연락처를 기준으로 가족을 일괄 차단하지 않는다.
- 제한은 요청마다 서버에서 적용하며 임의 클라이언트 헤더를 IP로 신뢰하지 않는다. rate limit 저장소 장애 시 공개 접수는 일시 오류를 반환하고 입력을 보존한다.
- 숨김 스팸 입력, 요청 본문 크기 제한, 허용 Origin 검증을 적용한다. 담당자는 공개 제한과 독립된 인증 경로로 대리 접수할 수 있다.
- 교육·개인정보 응답은 공유 캐시나 정적 공개 결과물에 저장하지 않는다. 공개 응답과 내부 조회 로그에도 전체 신청 내용을 기록하지 않는다.

## 12. 기존 데이터 전환과 배포 순서

### A. 읽기 조사·백업

1. 실제 DB의 테이블·필드·인덱스·정책·함수·트리거와 로컬 SQL 차이를 기록한다.
2. 학기별 실제 순원 수, 신청 상태별 건수, member_id 누락, 같은 학기 복수 순 소속, 존재하지 않거나 다른 학기의 배정 순을 조사한다.
3. 원본 백업과 전환 전 집계 결과를 접근 제한된 위치에 보관한다. 개인정보 원문을 Git 문서나 일반 로그에 넣지 않는다.
4. 기존 코드·운영 DB가 이미 달라졌다면 이 문서의 변경 목록을 업데이트한 뒤 구현한다.

### B. 호환 가능한 구조 확장

1. 신규 모집·운영자·작업 이력 테이블과 nullable 필드를 먼저 추가한다. 공개 모집은 draft로 생성한다.
2. 기존 신청을 학기별 과거 모집에 연결한다. 당시 날짜를 알 수 없으면 과거 자료임을 표시하고 임의 모집 날짜를 만들지 않는다.
3. 기존 신청 상태·배정 순을 legacy_snapshot에 그대로 보존한다. 기존 pending은 재대조 가능한 pending, cancelled는 cancelled로 전환한다.
4. 기존 assigned 중 실제 성도 연결·명단 일치가 확인되지 않은 것은 legacy_review로 둔다. 기존 배정은 ‘과거 기록’으로 보이고 실제 확정 순원 수에 섞지 않는다.
5. 실제 명단과 일치하는 과거 배정도 확인자·확정 시각을 만들어내지 않는다. 기존 출처 이력을 유지한 별도 전환 확인 작업을 거쳐 새 확정 기록을 만든다.
6. 순원 season_id를 순 테이블에서 채운다. 복수 소속 충돌을 보고서로 분류하고 확인된 수정 이후 고유 제약을 적용한다. 충돌이 있으면 임의 삭제하지 않고 전환을 중단한다.

### C. 쓰기 경로 전환

1. 서버 확정 함수, 권한 함수, 새가족순 배정, 기존 멤버 배정·이동·제외·삭제 경로를 함께 수정한다.
2. feature flag 아래 새 화면을 배포하되 공개 신청 버튼은 아직 노출하지 않는다.
3. 실제 전환 시 기존 순원·신청 쓰기를 잠시 중지하고 최종 변경분을 대조한다. 읽기 화면에는 점검 상태를 표시한다.
4. 기존 공개 INSERT/넓은 쓰기 정책과 구 summer 제출 경로를 닫고 새 경로만 활성화한다. 권한 축소는 구버전 앱이 쓰기를 계속하는 동안 먼저 적용하지 않는다.
5. 신규 DB 제약과 앱이 호환되는지 내부 시험 후 쓰기를 재개한다. 모집을 published로 전환하고 웹사이트 링크·QR을 공개한다.

### D. 되돌리기

- 문제가 있으면 먼저 공개 모집을 paused로 바꾸고 새 확정 쓰기를 중지한다. 접수된 자료를 삭제하지 않는다.
- 실제 신규 신청·배정이 저장된 뒤에는 과거 백업으로 DB를 덮어쓰거나 구버전 앱의 자유로운 직접 쓰기를 복구하지 않는다.
- 새 스키마를 유지한 호환 앱으로 되돌리거나 수정 배포한다. 잘못된 특정 배정은 이력 기반 복구 작업으로 보정한다.
- 새가족 접수·출석·성도 조회에 영향이 있는지 확인하고 복구 전후 집계를 대조한다.

### 화면 인수 시나리오

1. 시험 모집과 순 A/B를 만들고 기존 성도 3명, 같은 번호 가족 2명, 신규 1명, 연락처 변경 1명, 중복 1건으로 접수한다. 모든 데이터는 합성 자료다.
2. 자동 일치 목록에서 순을 지정해 한 번에 확정한다. 성도 연결 버튼을 별도로 누르지 않아야 한다.
3. 연락처 변경·중복 신청을 남긴 상태로 다른 사람의 확정을 끝낸다.
4. 예외 상세에서 기존 성도 연결·대표 신청 선택·신규 준비를 처리하고 나머지를 확정한다.
5. 순별 명단·출석·성도 상세에서 대상과 수를 대조한다.
6. 휴대전화로 QR 스캔, 신청, 마감 화면, 입력 오류, 네트워크 재시도를 확인한다.
7. 관리자·모집 담당·순장·비로그인 화면을 각각 검증한다. 키보드 탭 이동과 오류 안내도 확인한다.

성능 목표: 합성 신청 500건·순 30개에서 페이지당 50건을 서버 조회하고 행별 추가 요청 없이 표시한다. 초기 목록과 배정안 저장의 서버 처리 p95 2초 이내, 100건 확정 5초 이내를 시험 환경 목표로 둔다. 실측 전 성능 달성을 주장하지 않는다.

## 17. 완료 산출물

- 학기별 3개 탭과 자동 대조·예외 처리·일괄 확정이 작동하는 앱 변경.
- 계정 없는 공개 신청서, 모집 고정 링크, QR 다운로드, 웹사이트 진입 버튼.
- 단계별 DB 마이그레이션, 전환 조사 결과, 제한된 권한 정책, 복구 절차.
- 실제 DB를 포함한 인수 테스트 결과와 기존 기능 회귀 결과.
- 운영자를 위한 짧은 사용 안내: 모집 열기 → 신청 확인 → 순 지정 → 확정 → 연락 후 안내 완료.
- 보존된 과거 자료와 해결되지 않은 전환 예외 목록. 예외를 삭제하거나 성공으로 숨기지 않는다.
