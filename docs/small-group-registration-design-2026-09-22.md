# 로그인 없는 순신청·성도 연결·순배정 설계

작성: 2026-09-22 / 담당: Media & Tech Owner

상세 구현 기준은 [이음 순신청·배정 구현 상세 설계안](./small-group-registration-implementation-spec-2026-09-22.md)을 따른다. 탭 구성, 필드, API, 전환 및 테스트 기준이 구체화되었으며 차이가 있으면 상세 설계안이 우선한다.

상태: 구현 전 설계안. 로컬 코드와 사역 문서를 확인했으며 운영 DB 및 배포 상태는 검증하지 않았다. 모집 날짜·대상·배정 기준은 미확정이다.

## 1. 결정과 범위

- 성도는 QR 또는 웹사이트에서 로그인 없이 신청한다.
- 웹사이트는 모집 안내와 신청 진입을 담당하고, 앱의 공개 신청서 한 곳에서 접수한다.
- 이름·연락처가 유일하게 일치하는 신청은 자동으로 성도 후보를 붙여 배정 대기에 보낸다. 담당자는 별도 연결 작업 없이 배정 확정 시 함께 연결하며, 예외 신청만 개별 확인한다.
- 성도 기록의 `members.id`가 개인 식별의 기준이다. 로그인 계정은 필요하지 않다.
- 이번 단계는 접수, 성도 확인, 배정안, 실제 순원 반영, 안내 여부 기록까지다.
- 개인 포털, 자동 문자·카카오 발송, 신청자가 직접 순을 고르는 기능은 별도 후속 범위다.

## 2. 현재 구조에서 확인한 내용

| 현재 구현 | 설계에 미치는 영향 |
| --- | --- |
| `/summer-apply` 공개 신청서, 이름·연락처·메모 접수 | 공개 신청 UI와 저장 구조를 재사용한다. 여름 전용 문구는 모집 설정으로 교체한다. |
| 활성 시즌을 조회해 접수 대상 결정 | 운영 학기와 모집 대상을 분리한다. 다음 학기 모집 때문에 현재 학기를 바꾸면 안 된다. |
| `small_group_applications.member_id` 존재 | 자동 후보와 확정 연결을 구분하고, 성도 연결은 배정 확정에 통합한다. |
| 배정 시 신청서의 상태와 `assigned_group_id`만 변경 | 확정 처리 시 실제 `small_group_members`까지 같은 작업으로 저장해야 한다. |
| 순 목록이 실제 순원과 배정된 신청서를 합쳐 표시 | 전환 이후 연결 완료 신청서는 중복 표시하지 않도록 조회를 수정한다. |
| `new_family.member_id`와 교육 진도·수료 기록 존재 | 신청자가 연결되면 교육 상태를 기존 원본에서 읽는다. 신청서에 교육 상태를 복제하지 않는다. |
| 새가족 접수 시 활성 시즌 새가족순 자동 편성 | 정규 순 확정 시 같은 시즌 새가족순에서 이동하는 절차가 필요하다. |
| 기존 공개 신청 정책은 직접 INSERT 허용 | 새 접수 경로만 제한해도 우회 가능하다. 기존 정책까지 함께 변경한다. |

In the Beginning 기획 문서에는 새가족과 기존 멤버가 함께하는 3주 프로그램으로 기재되어 있다. 기존 멤버에게 새가족 기록이 없다는 이유로 교육 미이수라고 표시해서는 안 된다. 전체 프로그램 출석 관리가 필요하면 별도 교육 참여 기록 범위로 설계한다.

## 3. 성도 화면

### 입구와 주소

- 웹사이트에 ‘순신청’ 안내 카드와 버튼을 둔다.
- QR과 웹사이트 버튼은 동일한 앱 주소를 가리킨다.
- 일반 주소 제안: `/group-apply`. 현재 공개 모집 안내를 보여준다.
- 모집별 주소 제안: `/group-apply/[모집코드]`. QR은 이 고정 주소를 사용한다.
- 마감된 QR은 해당 모집의 마감 안내를 유지한다. 다음 모집으로 조용히 바꾸지 않는다.
- 여러 모집이 동시에 열리면 일반 주소에서 모집명·대상을 보고 선택한다.
- 과거 `/summer-apply`는 과거 모집 종료 안내를 유지하고 새 안내로 이동할 버튼을 제공한다.

### 신청서

| 항목 | 기본안 | 목적 |
| --- | --- | --- |
| 이름 | 필수, 성과 이름을 한 칸에 입력 | 기존 명단과 대조. 신규 성도 생성 시 담당자가 이름 구성을 확인한다. |
| 연락처 | 필수, 국가번호 포함 입력 지원 | 성도 후보 대조와 배정 안내. 미국 번호를 기본으로 제시하되 다른 국가도 지원한다. |
| 신청 구분 | 신규 참여 / 계속 참여 / 변경 희망 | 대상에 맞춰 모집별로 표시한다. |
| 배정 참고사항 | 선택, 짧은 자유 입력 | 모임 가능 시간 등 필요한 요청. 민감한 상담 내용은 별도 연락을 안내한다. |
| 정보 이용 안내 확인 | 필수 | 사용 목적·열람 담당·보관 기준·문의 경로를 모집 안내에 명시한다. 운영 문구 확정 후 공개한다. |

생년월일·주소·교육 수료 여부는 기본 신청 항목에 넣지 않는다. 추가 배정 기준이 확정될 때 필요한 항목만 더한다. 연락처가 없거나 온라인 작성이 어려우면 담당자가 내부 화면에서 사유와 함께 대리 접수한다.

완료 화면에는 모집명, 접수 완료, 배정 안내 예정 문구, 수정·취소 문의 경로를 표시한다. 접수는 배정 확정을 의미하지 않는다. 첫 버전은 본인 조회·수정을 제공하지 않으며, 수정·취소는 담당자가 확인 후 처리한다. 접수번호를 제공하더라도 본인 인증 수단으로 사용하지 않는다.

## 4. 담당자 화면

기존 ‘순 편성 > 학기’ 안에 ‘신청 관리’를 둔다.

- 상단: 유효 신청 / 자동 일치 / 예외 확인 필요 / 배정 대기 / 배정 확정 수.
- 탭: 전체, 확인 필요, 배정 대기, 배정안, 확정, 중복·취소.
- 목록: 이름, 연락처, 신청 구분, 성도 연결, 교육 상태, 현재 순, 희망사항, 제안 순, 처리 상태.
- 상세: 원본 신청, 기존 성도 후보, 교육 이력, 기존 배정, 담당자 처리 이력.
- 모집 관리: 대상 학기, 모집명, 안내, 접수 시작·마감, 수동 중지, 신청 링크, QR 다운로드.

‘미신청자’는 전체 모집 대상 명단이 별도로 확정된 경우만 표시한다. 전체 성도 수에서 신청 수를 단순 차감하지 않는다.

## 5. 성도 연결 병목을 줄이는 자동 분류

모든 신청자에게 별도 ‘성도 연결 확인’을 요구하지 않는다. 접수와 배정안 작성은 성도 연결 전에도 가능하게 하고, 실제 명단 반영 시에만 성도 식별을 완료한다.

| 조건 | 자동 처리 | 담당자 작업 |
| --- | --- | --- |
| 정규화한 이름+전체 연락처가 한 성도와 일치하고 충돌 없음 | 자동 일치 표시, 성도 후보 연결, 배정 대기로 이동 | 순을 검토한 뒤 ‘연결·배정 확정’으로 함께 처리 |
| 이름만 일치, 연락처 변경·누락, 복수 후보, 중복 신청 | 확인 필요로 분류, 후보와 불일치 이유 표시 | 예외만 기존 기록 대조 |
| 후보 없음 | 신규 확인 목록에 표시, 미연결 상태로 배정안 작성 허용 | 신규 여부 확인 후 기록 생성과 배정 확정을 한 흐름으로 처리 |

1. 신청 원문과 검색용 정규화 값을 별도로 보관한다. 이름 공백과 연락처 국가번호·구두점을 정리한다. 철자 유사도, 전화번호 뒤 네 자리, 이름만의 일치는 자동 연결 근거로 쓰지 않는다.
2. 자동 일치는 내부 업무를 위한 후보 연결이다. `candidate_member_id`와 확정된 `member_id`를 구분하고 근거·대조 시각을 저장한다. 본인 인증이나 기존 정보 수정 권한으로 사용하지 않는다.
3. 자동 일치 건에는 별도의 연결 버튼을 누르지 않는다. 배정 검토 목록에서 이름·마스킹된 전화·현재 순·제안 순과 ‘성도 연결도 함께 확정’ 안내를 보여주고 선택 일괄 확정을 지원한다.
4. 가족 공용 번호여도 이름+번호 조합이 유일하고 다른 충돌이 없으면 자동 후보가 될 수 있다. 번호 하나만으로 동일인으로 판단하거나 가족의 신청을 차단하지 않는다.
5. 자동 일치하지 않아도 접수나 배정안 작성은 막지 않는다. 연결되지 않은 항목만 실제 명단 확정 대상에서 구분한다. 담당자가 배정안을 만드는 동안 예외 목록을 따로 정리할 수 있다.
6. 신규 기록 생성은 담당자 확인 후 수행한다. 폼 제출만으로 성도·새가족·교육 기록을 만들거나 기존 이름·연락처를 덮어쓰지 않는다. 성도 연결은 정식 교인 등록과 별개다.
7. 같은 모집의 같은 성도로 확인된 신청은 하나의 유효 신청만 유지한다. 재신청은 자동 덮어쓰기 대신 변경 내용만 비교해 대표 신청을 선택한다.
8. 확정 직전에 후보 유일성·충돌·기존 배정을 다시 검사한다. 대조 후 연락처 변경, 기록 병합, 추가 중복 신청이 발생했으면 예외로 돌린다. 연결을 잘못 확정한 경우 원문과 이력에 따라 바로잡을 수 있게 한다.

모집 전에는 이름·연락처 누락과 중복 조합만 점검한다. 이를 전체 성도 정보 정비 사업으로 확대하거나 접수 시작의 필수 조건으로 만들지 않는다. 자동 일치율과 예외 건수는 실제 신청으로 측정하며 사전 수치를 가정하지 않는다.

한 번의 제출이 재시도로 두 번 저장되지 않도록 제출 식별키를 사용한다. 별도 제출의 이름·연락처 중복은 검토 신호로만 사용한다. 중복 처리한 원문은 대표 신청과 연결해 남긴다.

## 6. 교육 상태와 배정 기준

- 연결된 성도의 교육 상태는 기존 새가족교육 로직에서 조회한다: 미참여, 참여 중, 수료, 기록 확인 필요. 자동 후보 단계의 교육 상태는 내부 화면에서 ‘자동 대조 기준’으로 표시하고, 배정 확정 때 다시 확인한다.
- 해당 교육 기록이 없으면 ‘기록 없음’으로 표시한다. 이를 미이수로 단정하지 않는다.
- 교육 수료, 정식 등록, 순배정은 각각 별개 상태다.
- 기본안은 교육 상태를 참고 정보로 제시하고 담당자가 배정하는 방식이다.
- ‘수료자만 정규 순으로 이동’ 같은 사역 기준은 확정 후 적용한다. 확정 전에는 시스템이 임의로 신청을 거절하지 않는다.
- 일반 순장은 자기 순의 확정 명단만 본다. 전체 신청·교육 이력·배정 메모는 모집 담당자 권한으로 제한한다.

## 7. 배정과 상태

성도 확인 상태와 신청 처리 상태를 분리한다.

- 성도 확인: 자동 일치 / 예외 확인 필요 / 신규 확인 → 연결 완료. 자동 일치는 배정 확정 때 연결 완료로 전환한다.
- 신청 처리: 접수 → 배정 대기 → 배정안 → 확정. 별도로 중복·취소 상태.
- 안내 여부: 미안내 / 안내 완료. 배정 확정이 자동 안내를 뜻하지 않는다.

배정안에서는 실제 명단을 바꾸지 않고 제안 순을 저장한다. 담당자가 교육 상태, 현재 순, 요청사항, 순별 인원을 보고 개별 또는 선택 일괄 확정한다.

확정 조건과 처리:

1. 확정된 성도 또는 유일성이 재검증된 자동 후보, 유효 신청, 대상 학기·순 일치, 담당 권한을 서버와 DB에서 검증한다. 자동 후보는 성도 연결과 순배정을 함께 확정한다.
2. 이미 같은 학기의 다른 순에 있으면 기존 순 → 새 순 이동을 보여준다. 새가족순도 같은 규칙을 따른다.
3. 기본 운영 규칙은 한 학기에 한 성도당 한 순이다. 다중 소속 예외가 필요하면 별도로 정의한다.
4. 확정 시 성도 연결(필요하면 담당자가 확인한 신규 기록 생성), 기존 같은 학기 배정 이동, 실제 순원 저장, 신청 확정, 담당자·시간·변경 전후 이력을 한 트랜잭션으로 처리한다. 다른 학기 이력은 보존한다.
5. 같은 성도·학기의 동시 배정은 DB 잠금과 무결성 제약으로 막는다. 개별 배정 등 다른 진입점에도 동일 규칙을 적용한다.
6. 일괄 확정은 해결되지 않은 예외를 선택 대상에서 구분하고 나머지 선택 항목을 먼저 검증해 한 작업으로 처리한다. 검증 이후 충돌이 생기면 선택 작업을 롤백하고 충돌 항목을 표시한다. 담당자는 해당 항목을 제외한 나머지를 다시 확정할 수 있다.
7. 확정 전 신청 취소는 배정안만 해제한다. 확정 후 취소는 실제 순 소속 변경을 포함하는 별도 작업이다. 중간에 다른 변경이 있었다면 과거 순을 자동 복구하지 않고 재확인한다.

## 8. 저장 구조 제안

| 저장소 | 책임과 주요 항목 |
| --- | --- |
| `members` | 기존 성도 원본. 로그인 계정과 독립된 ID 유지. |
| `new_family`, 기존 교육 기록 | 기존 교육·등록 원본. 신청 관리에서 읽기 연결. |
| `small_group_seasons` | 실제 운영 학기. 모집 개설과 활성화는 별개. |
| 신규 `small_group_campaigns` | 모집 코드, 대상 학기, 대상·안내, 신청 항목, 시작·마감 시각, 시간대, 공개·중지 상태, 안내·동의 문구 버전. |
| 확장 `small_group_applications` | 모집 ID, 입력 원문, 정규화 이름·전화, 제출 식별키, 후보 성도 ID·매칭 근거·대조 시각, 확정 성도 ID, 연결 상태, 신청 구분, 처리 상태, 제안 순, 확정 순, 중복 대표 ID, 안내 여부, 동의 시각·버전. |
| `small_group_members` | 출석·돌봄에 사용하는 확정 순원 원본. 성도·학기당 한 배정 제약과 순의 학기 일치 제약 추가. |
| 신규 처리 이력 | 연결·중복·배정·이동·취소·안내의 변경 전후, 수행자, 시각. 원본 삭제 대신 상태 변화 기록. |

모집 ID가 대상 학기를 결정한다. 신청서의 기존 `season_id`를 유지한다면 모집의 학기와 DB 제약으로 일치시킨다. 순원 테이블에 학기 ID를 추가할 경우 순-학기 복합 참조로 무결성을 보장한다.

## 9. 공개 접수와 권한

- 공개 사용자는 모집 안내 조회와 새 신청 제출만 가능하다. 기존 성도 검색, 신청 목록, 교육 상태, 연락처는 반환하지 않는다.
- 저장 시 서버가 모집 상태·시각·입력 길이·허용 항목을 검증한다. 화면을 열어 둔 뒤 마감되어도 제출 시 차단한다.
- 마감은 교회 시간대로 입력·표시하고 절대 시각으로 저장한다. 기본 제안 시간대는 America/New_York.
- 공개 입력으로 `member_id`, 배정 상태, 순, 담당자, 관리 메모를 지정할 수 없게 한다.
- 기존 익명 직접 INSERT 정책을 제거·축소하고 검증된 접수 경로만 허용한다. 호출 제한을 우회하는 직접 DB 경로를 남기지 않는다.
- 서버 접수 빈도 제한과 숨김 스팸 필드를 기본 적용한다. 외부 발송이나 휴대전화 인증 서비스는 첫 버전에 의존하지 않는다.
- 신청 접수 응답은 기존 성도 존재 여부나 중복 후보를 공개하지 않는다.
- 관리자: 모집 설정과 전체 처리. 다락방장: 명시적으로 지정된 모집 담당 범위에서 처리. 순장: 자기 순 확정 명단 조회. 화면뿐 아니라 DB에서도 제한한다.

## 10. 기존 데이터 전환과 구현 순서

1. 운영 DB의 실제 정책·적용 이력·중복 명단을 읽기 점검하고 백업한다. 로컬 SQL만 보고 현재 운영 상태를 단정하지 않는다.
2. 모집 구조, 성도 연결 상태, 처리 이력, 권한을 추가한다. 기존 여름 신청은 과거 모집으로 구분하고 보존한다.
3. 기존 배정 신청 중 성도 연결 완료/미완료, 실제 순원과 중복/충돌 여부를 보고서로 분류한다. 추정으로 일괄 연결하지 않는다.
4. 공개 신청서와 모집 설정을 구현하고, 기존 여름 경로의 직접 제출도 닫힘 상태를 지키게 한다.
5. 신청 검토·성도 연결·배정안·확정 작업을 구현한다. 모든 기존 순배정 진입점을 같은 확정 규칙에 맞춘다.
6. 실제 순원과 신청서를 합치는 기존 화면의 중복 표시를 해소한다. 미연결 과거 신청은 별도 ‘기존 신청 확인 필요’ 목록으로 보존한다.
7. 시험 환경에서 접수부터 출석 명단 반영까지 검증하고 모집 대상·기간·교육 기준을 설정한다.
8. DB와 앱의 호환 배포를 완료한 뒤 공개 접수를 열고, 웹사이트 버튼·QR을 노출한다.

## 11. 구현 완료 기준

- 비로그인 모바일에서 QR → 신청 → 접수 완료가 동작한다.
- 현재 운영 학기를 변경하지 않고 다음 학기 모집을 받는다.
- 마감 직전 열린 화면, 과거 주소, 직접 호출에서도 마감·권한 검증이 적용된다.
- 제출 재시도는 한 번만 저장되고 동명이인·가족 번호·재신청은 잘못 합쳐지지 않는다.
- 자동 일치 신청은 개별 연결 클릭 없이 배정 대기에 들어가며 연결·배정을 함께 확정할 수 있다. 예외가 남아 있어도 다른 신청자의 배정은 진행된다.
- 자동 후보는 공개 정보 조회나 기존 성도 수정 권한을 주지 않는다. 확정 전 후보가 달라지면 재검증으로 차단한다.
- 성도 연결 후 교육 상태가 기존 화면과 일치하고, 기록 없음이 미이수로 오인되지 않는다.
- 배정안은 실제 명단을 바꾸지 않는다. 확정은 실제 순원과 신청 상태를 함께 반영한다.
- 새가족순 이동, 같은 학기 중복 배정, 동시 확정, 실패 시 롤백을 검증한다.
- 확정된 성도가 순 편성·출석·성도 상세에서 동일하게 나타난다.
- 익명·승인 대기·일반 순장 계정은 허용되지 않은 신청·교육 정보를 읽거나 변경하지 못한다.
- 기존 여름 신청, 과거 학기, 교육 기록은 보존되고 중복 표시되지 않는다.
- 저장·목록 조회 실패를 성공이나 신청자 0명으로 숨기지 않는다. 기존 소그룹 동작과 관련 테스트, 린트, 빌드가 통과한다.

## 12. 공개 전에 확정할 운영 값

- 모집명과 대상: 전체 재신청 / 신규·변경만 신청 등.
- 접수 시작·마감과 배정 안내 시점.
- 교육 수료 여부를 배정 조건으로 삼을지 여부.
- 순배정에 필요한 추가 질문, 처리 담당자와 담당 범위.
- 문의 경로, 개인정보 이용 안내와 보관 기준.

이 값들은 설정으로 분리한다. 미확정 상태에서도 구조와 검토 화면을 구현할 수 있지만, 임의 날짜·기준으로 공개하지 않는다.
