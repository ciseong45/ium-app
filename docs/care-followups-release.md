# 돌봄 후속 조치 — 적용 준비본

## 현재 상태

기록 오류 수정은 main의 `0032eb7`에 반영했다. 새 돌봄 기능과 출석 저장 트랜잭션은 `feat/care-followups`에서 검증했으며, 운영 DB 적용 전에는 main에 병합하지 않는다.

운영 Supabase 변경은 자동 승인 검토에서 거절됐다. 거절 이유는 운영 함수·트리거·테이블·접근 정책을 바꾸는 위험이었다. 운영 변경을 우회하지 않고, 별도의 메모리 PostgreSQL에서 검증했다. 기존 운영 데이터와 개인 기록은 사용하지 않았다.

## 사용자에게 생기는 변화

- 대시보드·메뉴의 **이번 주 돌봄**에서 내 담당, 인계 요청, 기한 초과, 미배정, 완료·취소를 확인한다.
- 관리자가 사람 상세에서 다음 할 일과 기한을 등록한다. 담당자는 로그인 계정이다.
- 다른 담당자를 지정하면 인계 요청으로 등록된다. 상대가 수락할 때까지 기존 담당자가 유지된다. 거절하면 기존 담당자가 계속 맡는다.
- 완료·보류·취소·재개·인계에는 처리 내용이 필요하다. 보류와 재개에는 다음 기한도 필요하다.
- 모든 성공한 변경은 수행자와 시각을 포함한 이력으로 남는다. 다른 사람이 먼저 수정하면 오래된 화면의 저장을 거절한다.
- 새가족의 신앙·정착 상태는 자동으로 바꾸지 않는다. 기존 새가족 담당자(`members.id`)와 돌봄 담당 계정(`profiles.id`)을 자동으로 혼합하지 않는다.
- 출석을 해제하고 저장하면 기존 기록이 지워진다. 한 번의 저장은 전부 성공하거나 전부 취소된다. 순장은 자신의 활성 순, 다락방장은 자신의 활성 다락방 순만 저장한다.

## 접근 범위

신규 돌봄 등록은 관리자에게만 허용된다. 항목과 이력은 승인된 계정 중 관리자·등록자·현재 담당자·인계 수신자만 조회한다. 일반적인 변경은 관리자와 현재 담당자, 수락·거절은 지정된 수신자만 할 수 있다. 직접 테이블을 수정해 이력을 우회할 수 없다. 개인 총괄(`cc_*`) 정보는 연결하지 않는다.

기존 own-profile 정책을 통한 역할·연결 멤버 변경을 막는 트리거를 추가한다. 승인된 관리자의 기존 역할 변경 기능은 유지된다.

## 운영 적용 대상과 순서

승인 후 IUM Supabase 프로젝트 `xrahwxkchwxxipggwiff`에 아래 순서로 적용한다.

1. `supabase/20260908-care-foundation.sql`: 돌봄 항목·이력, 상태 변경 함수, 행 접근 정책, 프로필 권한 보호.
2. `supabase/20260908-attendance-integrity.sql`: 순별 출석 권한, 출석 일괄 저장 함수. 기존 `attendance_auth_*` 4개 정책을 담당 범위 정책으로 교체.
3. 함수·테이블·정책 존재와 실제 로그인 권한을 확인한 뒤 PR을 main에 병합하고 Vercel 배포를 확인.

각 SQL은 BEGIN/COMMIT 트랜잭션으로 묶었다. 기존 멤버 상태나 출석 기록을 일괄 수정하지 않는다. 삭제 기능은 사용자가 출석 체크를 명시적으로 해제하고 저장한 대상·날짜에만 적용된다. SQL은 1회 적용용이므로 재실행 전 적용 여부를 확인해야 한다. 운영 적용 전 승인과 스키마 재확인이 필요하다.

## 검증

- 앱 전체 단위/화면 테스트, TypeScript, lint, Next.js production build.
- `scripts/verify-care-sql.mjs`: 임시 PostgreSQL에서 실제 SQL 실행과 33개 검사. 인계·수락·거절, 처리 내용, 이력, 오래된 버전 충돌, 승인 대기·다른 순 권한, 직접 수정 금지, 권한 상승 차단, 출석 저장 원자성·해제를 포함한다.
- 로컬 검증은 운영 Supabase 설정 전체와 동일한 통합 테스트를 대체하지 않는다. 운영 환경 확인은 승인 후 진행한다.

재현 예시(임시 검증 의존성만 설치하며 앱 의존성은 바꾸지 않음):

```sh
npm install --prefix /tmp/ium-sql-check @electric-sql/pglite --ignore-scripts --no-audit --no-fund
PGLITE_MODULE=/tmp/ium-sql-check/node_modules/@electric-sql/pglite/dist/index.js node scripts/verify-care-sql.mjs
npm test -- --runInBand
npm run lint
npm run build
```

로컬 SQL 엔진은 [PGlite 공식 문서](https://pglite.dev/docs/)의 메모리 PostgreSQL 실행 방식을 사용했다.

## 이번 범위 밖의 후속 개선

방문자 등록의 멤버·새가족 원자적 생성, 신청자와 기존 사람의 명시적 연결, 실제 정착 근거, 과거 출석 명부 보존은 별도 변경으로 진행한다. 기존 자동 이탈 기록을 추측해 일괄 복원하지 않는다.
