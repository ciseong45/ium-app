# 순신청 기능 적용·운영 안내

상태: 로컬 구현 및 검증. 운영 Supabase 적용과 웹사이트·앱 배포는 아직 하지 않았다.

## 적용 전 확인

1. 운영 DB에서 `supabase/20260922-small-group-registration-preflight.sql`을 읽기 전용으로 실행한다. 처음 네 예외 조회가 모두 0건이어야 하며 기존 정책·트리거·교육 테이블을 로컬 SQL과 대조한다. 실제 구조가 다르면 마이그레이션을 먼저 수정한다.
2. `small_group_applications`의 기존 상태별 건수와 `small_group_members`의 학기별 순원 수를 기록하고 운영 백업을 만든다.
3. 앱 배포 환경에 `SUPABASE_SERVICE_ROLE_KEY`와 임의의 긴 `GROUP_APPLY_RATE_SECRET`을 서버 전용 변수로 설정한다. 값을 브라우저 공개 변수나 저장소에 기록하지 않는다.
4. 공개 모집명·대상·신청 기간·문의 경로·정보 이용 안내·보관 검토일을 운영자가 확정한다. 설정 없이는 모집을 공개할 수 없다.

2026-09-22 운영 DB 읽기 조사: 같은 학기 중복 순 소속 0건, 신청과 배정 순의 학기 불일치 0건, 대기 신청의 동일 성도 중복 0건, 과도하게 긴 학기명 0건. 기존 신청 24건(배정 23, 취소 1), 현재 순원 74명. 교육 과정·참여 테이블과 `current_week` 필드가 있다. 과거의 넓은 신청·순원 정책 13개가 존재하며 이 마이그레이션에서 해당 정책명을 모두 제거한다. 실제 마이그레이션 직전에 숫자와 정책을 다시 확인한다.

## 적용 순서

1. 호환 앱을 빌드하고 DB 적용 시각을 정한다. 현재 순원·신청 변경을 잠시 멈춘다.
2. `supabase/20260922-small-group-registration.sql`을 운영 DB에 적용한다. 오류가 나면 트랜잭션 전체가 롤백된다. 중복 소속이나 다른 학기 순 참조를 추측으로 삭제하지 않는다.
3. 앱을 배포한다. 기존 여름 신청 주소는 종료 안내로 바뀌고, 새 공개 신청은 기본적으로 모집이 없으므로 닫힌 상태다.
4. 관리자 화면에서 시험 모집을 draft로 만들고 QR, 공개 신청서, 자동 후보, 배정안, 실제 명단 반영을 합성 자료로 확인한다. 시험 자료는 실제 성도와 섞지 않는 별도 시험 DB가 안전하다.
5. 실제 모집을 published로 바꾸고 앱 링크를 확인한 다음 웹사이트 버튼을 배포한다. 휴대전화로 QR을 스캔해 공개 주소를 확인한다.
6. 학기별 확정 순원 수·신청 상태별 건수를 기록하고 기존 자료와 대조한다. 과거 여름 배정은 `legacy_review`로 남아 실제 명단에 자동 편입되지 않는다.

## 장애 시

- 공개 접수 오류: 모집을 paused로 바꾸고 기존 접수 자료는 보존한다. 공개 API, 서버 전용 변수, DB 함수 오류를 확인한다.
- 배정 오류: 해당 신청의 버전·성도 후보·학기·순을 다시 불러온다. 실제 순원과 신청 상태 중 하나만 반영됐다면 즉시 DB 트랜잭션 이력을 확인한다.
- DB 적용 후에는 운영 자료를 과거 백업으로 통째로 덮어쓰지 않는다. 이력에 근거해 개별 복구한다.

## 평소 운영

1. 모집 설정에서 학기와 기간을 정하고 링크·QR을 배포한다.
2. 신청·배정에서 자동 일치 건에 순을 지정한다. 확인 필요 건은 원본을 보존한 채 이름·연락처를 정정해 재대조하거나 기존 성도를 연결하고, 없는 경우에만 신규 성도를 준비한다. 각 조치의 사유를 기록한다.
3. 확정 창에서 이름과 대상 순을 확인해 연결·배정을 함께 확정한다.
4. 실제로 성도에게 알린 다음 ‘안내 완료’를 기록한다. 이 기능은 메시지를 자동 발송하지 않는다.
5. 과거 자료와 중복·취소 신청은 기록으로 보존한다. 이름·연락처만으로 성도를 임의 합치지 않는다.

## 검증 명령

```bash
npm test -- --runInBand
npm run lint
npm run build
node scripts/check-small-group-registration.mjs /path/to/@electric-sql/pglite/dist/index.js
```

웹사이트 변경은 웹사이트 저장소에서 `npm run lint && npm run build`로 확인한다. 로컬 PGlite 검증은 운영 DB의 실제 자료·정책을 대신하지 않는다.
